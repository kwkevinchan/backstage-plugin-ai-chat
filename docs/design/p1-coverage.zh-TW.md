規格裡所有標 P1 的需求，各自對到哪些測試。這是 P1-11 的驗收：每一條都有至少一個測試，沒有只靠文件的需求。

## 結論

- P1 需求共 **35 條**（H 11、T 8、P 1、S 3、SE 1、O 1、A 9、B 1）。**35 條都有測試**。
- P1-11 新增的測試補了這幾條：H-08（串流的結果和存下的相同）、S-01（核心不能執行程式碼或碰檔案系統）、S-02（不載入圖片）；H-04、H-11、T-07、A-06 補了兩台 backend 的情形。
- 純文件的需求沒有。有兩條要說明測試的範圍：
  - **A-09** 的測試證明規則會擋（`lintRules.test.ts`），「CI 會擋」本身是 CI 設定（`.github/workflows/ci.yml` 跑 `yarn lint:all`），不是測試能證明的。
  - **S-01** 用靜態檢查：lint 規則（核心的 `domain/` 和 `application/`）擋掉：`fs`、`child_process`、`vm`、`worker_threads`、`cluster`、`module`、`net`、`http`、`https`、`dgram`（含 `node:` 前綴）的 import；`eval`、`new Function`；其他取得模組的寫法（`require`、`process`、`globalThis`、`global`、`module`、動態 `import()`、`import x = require()`；測試檔可用測試工具的全域）。這是原始碼的靜態檢查，不是沙箱，所以沒有執行期的測試。
- **A-10** 的意思：每個有「記憶體版和資料庫版」兩種實作的 port，兩種都通過同一組測試。P1 只有 `ItemLog` 是這樣（`InMemoryItemLog`、`KnexItemLog`），共用測試是 `itemLogContract`。其他 port 在 P1 只有一種實作，由各自的 adapter 測試負責。

## 兩台 backend 的整合測試

`宿主/integration/twoBackends.test.ts`（P1-11 新增）。兩台 backend 是兩組各自的 `createHost`、`RunSupervisor` 和模型，共用同一個資料庫（SQLite；CI 設了連線字串時是 PostgreSQL 16）和一個手動撥的時鐘。

| 情形                                                                                                             | 測試                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| A 開的 Run 等核准，B 收到核准後接手，工具只執行一次                                                              | lets B carry the run on and run the tool once, while A holds nothing                                                          |
| 兩台同時收到同一個決定：只有一個請求啟動迴圈，工具只執行一次，只有一筆 `approval`                                | runs the tool once when both backends get the same decision at the same time                                                  |
| 同上，走 HTTP 路由                                                                                               | does the same through the routes: the decision that B receives streams the rest of the run                                    |
| A 關機只結束 A 自己的 Run；B 的 Run 和沒有租約的等核准 Run 都不動                                                | the shutdown of one backend (H-11) › ends only the runs of that backend                                                       |
| A 當掉（沒有 `shutdown`）：租約沒過期時 B 不動它；過期後 `ExpireStaleRuns` 在 B 標成 `expired`，之後可以開新 Run | a backend that stops without a shutdown › is expired by ExpireStaleRuns on the other backend, and the session takes a new run |
| `GET /sessions/:id/stream` 打到不是跑 Run 的那台回 `204`（P1 已知限制，P2-06 補），跑 Run 的那台回 `200`         | GET /sessions/:id/stream on the backend that does not run the loop (P1 limit)                                                 |

已有的 `hostFlows.test.ts` 涵蓋其中幾個單台內的部分（另一台決定、關機接手、租約過期）；兩台測試補的是兩台同時決定、關機只動自己的 Run、HTTP 路由，以及 `GET /stream` 的限制。
