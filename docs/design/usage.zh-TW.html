AI Chat 用途說明

Backstage 裡的 AI Chat 是做什麼用的、誰會用到、怎麼用。這一頁給第一次接觸的人看，不需要先讀規格。

在 Backstage 裡用對話查資料、啟動工作。查詢直接做；會改東西的，每一次都要你按核准。 它能做的事，就是各個 plugin 註冊出來的 action。它自己不執行任何程式碼。
設計：已定案 實作：P1 已完成（對話、查詢、核准、工具組、多台部署） 下一步：P2
用來做什麼 誰會用到 對話長什麼樣 分享 做自己的 Agent 不做什麼 什麼時候有
一

用來做什麼

你說一句話，Agent 決定要用哪個工具。接下來走哪條路，只看那個工具會不會改東西。

你說的話 它做的事 要核准嗎 多久
payments-api 是哪個團隊的？ 查一次 catalog 不用 幾秒
昨天的部署為什麼失敗？相關的處理文件在哪？ 先列計畫，再查 workflow 紀錄和 TechDocs，回答附來源 不用 十幾秒到一分鐘
幫我重跑那個失敗的 workflow 顯示核准卡片，你按 Allow 後啟動 要，每一次 啟動幾秒；工作本身在 Temporal 跑
把這個服務所有相依套件升級並開 PR 啟動一個 workflow 去做，對話留下連結 要 幾分鐘到幾小時，不佔用對話
二

誰會用到

角色 用它做什麼 要寫程式嗎 從哪一期開始
使用者 問問題。看它查了什麼。核准或拒絕改動。隨時停止。決定這段對話要開哪些工具組 不用 P1（核准和查詢第 0 版就有）
被分享的人 看同事的排查過程，唯讀。想接手就複製成自己的對話繼續問 不用 P2
想做 Agent 的團隊 寫一段系統提示，選工具組，放幾份 SKILL.md。就有一個自己團隊的 Agent 只要設定檔。進階的才要寫 backend module P3
Plugin 作者 把自己 plugin 的功能註冊成 action。Chat 和外部的 MCP client 都能用。也可以在自己的頁面放一個「問 Agent」的按鈕 要 註冊 action 現在就可以；按鈕是 P2
管理員 設定模型、工具組、哪些工具要核准或禁用、各種上限、保存期限。看稽核紀錄 只要設定檔 P1

管理員看不到任何人的對話內容。他看得到的是稽核紀錄：誰在什麼時候核准或拒絕了哪個工具。

這是示意畫面，不能操作。工具名稱、說明和參數是例子。P1 的左側對話列表沒有自動標題，每一段都顯示 New conversation；第一輪結束後自動產生標題是 P2。

  • 核准的是卡片上那組參數。按下 Allow 之後執行的就是你看到的那一組，模型不能事後改。
  • 只有對話的擁有者能核准。同一張卡片只算一次，連按兩下不會執行兩次。
  • 可以隔很久才核准。核准時用的是你當下的身分，不是當初送訊息時的。
  • 關掉分頁不會丟結果。它會把手上這一段跑完並存起來，你回來就看得到。
  • 隨時可以停止。已經查到的結果會留著。

  • 圖片附件：支援 PNG、JPEG、WebP、GIF；上傳後會顯示縮圖，送出前可以移除，重新整理後仍看得到。模型不支援圖片時不顯示 Attach。
  • 進行中插入（Enter）：訊息會顯示在輸入框上方的「Waiting to be read」，模型在下一個步驟讀入後出現在對話裡。若這輪還沒讀到就結束，會標示未讀。
  • 排隊（Ctrl+Enter／Cmd+Enter）與「現在就送」：停在等待核准時只能排隊。排隊中的訊息可以編輯、調整順序、刪除，或按 Send now 改成插入目前這輪；若上一輪失敗、取消或逾時，佇列會先暫停，等你按 Continue 或先送出一則新訊息。
四

分享

你可以把一段對話分享給同事或群組。對方只能看。分享有兩種，按下分享時選。

快照 持續更新
什麼時候用 把結果交給同事 幾個人正在一起查
對方看到的範圍 分享當下為止 一直到最新
分享之後的工具輸出 看不到（不在範圍裡） 預設不給看，你可以打開
到期 不會到期，你可以隨時取消 預設 24 小時，到期變成快照
你要管的事 沒有 畫面上方一直顯示正在分享給誰，旁邊有停止按鈕
  • 對方不能送訊息，也不能核准。多人在同一段對話裡發言不在這個設計的範圍。
  • 想接手就複製。複製出來的是對方自己的對話，帶走訊息和計畫，不帶工具輸出。他要用自己的權限重新查。
  • 分享給群組時會多一句提醒。之後才加入群組的人也看得到。
  • 分享、取消、複製都有稽核紀錄。
五

做自己團隊的 Agent

一個 Agent 是一份設定：系統提示、能用哪些工具組、帶哪些 Skill。大部分的團隊只要寫設定檔。

設定檔：定義 Agent

aiChat:
  agents:
    sre:
      title: SRE Agent
      systemPrompt: 你協助值班工程師排查服務問題。
        動手前先寫計畫，回答附上來源。
      toolsets: [catalog, techdocs, temporal]
      skills: [deploy-failure, rollback]
      planning: required   # 第一步一定先寫計畫

SKILL.md：一份做事方法

---
name: deploy-failure
description: 部署失敗時的排查順序
---
1. 找出最近一次部署 workflow 失敗在哪一步。
2. 逾時：查那一步相依的服務狀態。
3. 驗證失敗：把錯誤訊息和處理文件對照。
4. 要重跑之前，先說明原因再提出。
  • Skill 平常只佔一行。Agent 的上下文裡只有名稱和說明。它判斷用得上，才把全文載入。
  • Skill 用公開的 SKILL.md 格式。別的工具寫好的 Skill 可以直接拿來用。
  • 計畫是一張會更新的清單。Agent 查到新資訊會改計畫。你在畫面上看得到它做到哪一項。
  • 進階的才要寫程式。要加「每一步都帶上目前值班的人」這種資訊，或「凍結期不准啟動部署」這種規則，寫一個 backend module。
  • 你寫的規則只能把政策調嚴。它可以把一個工具改成要核准或直接拒絕，不能把要核准的改成不用。
六

它不做什麼

不做的事 原因 要做這件事的話
在 Chat 裡執行程式碼或指令 Backstage 的 backend 握有資料庫連線和所有 plugin 的金鑰 做成 Temporal workflow，由 Chat 啟動
不經核准就改東西 模型可能被它讀到的內容誤導 沒有例外。不是唯讀的工具不能設成免核准
幾個人在同一段對話裡發言 誰的權限、誰能核准會變得不清楚 用持續更新的分享一起看；要動手的人複製一份
記住上一段對話的內容 跨對話的記憶不在這一版 把要記的事寫成 Skill 或文件
讓管理員看對話內容 對話可能有個人的問題 看稽核紀錄

每一次執行有上限：步數、工具呼叫數、總時間。碰到上限它會停下來並告訴你，不會一直跑。

七

什麼時候有

分期 你可以用它做什麼
第 0 版（PR #1） 對話、查詢、核准後執行
P1 核心（已完成） 功能相同，底層換新：關掉分頁不丟結果、可以部署多台、長對話不會塞爆。新增：開關工具組、每段對話有自己的網址、Agent 知道你正在看哪一頁。部署時被中斷的一次執行會停在「The last run stopped before it gave an answer.」，旁邊有「Send the message again」可以重送。對話列表還沒有自動標題

P4 擴大 把大範圍的查詢分給子任務。Agent 的題組測試。在瀏覽器執行的工具
